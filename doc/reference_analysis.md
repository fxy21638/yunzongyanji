# 学长获奖代码分析与借鉴建议

> 参考项目：Front_Car V2.9.0（Infineon TC264D 双核）
> 当前项目：YG Smart Car（STC32G144K246 单核，Keil C251）
> 分析日期：2026-06-03

---

## 一、参考代码核心架构

```
摄像头原始图 (188×120)
    │
    ├─ Image_Copy()              复制原图
    ├─ Region_Otsu()             底部区域Otsu阈值
    ├─ Seek_Pts_Seed()           Canny边缘找种子点（左右边界起点）
    │
    ├─ findline_lefthand_adaptive()  ← 自适应阈值 + 右手法则爬墙追踪左边界
    ├─ findline_righthand_adaptive() ← 同上追踪右边界
    │   ↓ 得到稀疏点集 (original_pts)
    │
    ├─ PtsPerspective()          逆透视变换 → 鸟瞰图点集
    ├─ blur_points()             加权移动平均平滑
    ├─ resample_points()         等距重采样
    │   ↓ 得到 now_pts
    │
    ├─ find_corner()             角点检测（极值点 + 局部角度 + NMS）
    ├─ Ring_Process()            9状态圆环状态机
    ├─ cross_process()           2状态十字状态机
    │
    ├─ MidPts_Deal()             中线生成（选可靠边 → 偏移WIDTH/2 → 平滑 → 重采样 → 外推）
    ├─ Get_error_pure_pursuit()  Pure Pursuit 控制律 → 转向角
    │
    └─ PID_Position()            位置式PID → 舵机/电机输出
```

### 关键数据结构

```c
// 边界用稀疏点集表示（不是逐行数组）
BoundaryData {
    original_pts[188][2]  // 原始图像空间的边界点集 (x,y)
    original_step         // 有效点数
    now_pts[120][2]       // 鸟瞰图变换后的点集
    now_step              // 有效点数
    CornerMapping map[3]  // 3个候选角点（max_x, max_y, max_x*y）
    Lp_state              // 是否检测到拐点
    is_straight            // 边界是否为直线
}

// 中线也是点集
MidlineData {
    pts[188][2]           // 中线点集 (x,y)
    dist[188]             // 每个点到车体(94,120)的曼哈顿距离
    step                  // 有效点数
}
```

## 二、参考代码的核心技术优势

### 1. 逆透视变换 (Perspective Transform / Bird's-Eye View)

**原理**：求解 3×3 透视矩阵，将摄像头梯形畸变图像映射为俯视图。

**效果**：
- 车道宽度在鸟瞰图中**处处相等**，不受远近影响
- 弯道在鸟瞰图中呈现真实曲率，不会因透视变形
- 十字路口的直行方向宽度恒定，不会出现"远处变窄"的伪影

**当前项目的替代方案**：不做透视变换，用 `last_mid` 连续性约束 + 逐行扫描 + 中位宽度估算缺失边。在十字和急弯中，透视畸变会导致宽度异常，需要大量特殊处理。

### 2. Canny 边缘检测 + 自适应阈值爬墙追踪

**参考代码的边界提取方法**：
1. **种子点**：在底部某行用 Canny 算子（梯度幅值 + 方向）找到左右边缘
2. **爬墙追踪**：从种子点出发，用**右手法则**沿边界向上爬
   - 每步检查前方像素和左前/右前方像素（相对于前进方向）
   - 使用**自适应阈值**（局部 5×5 窗口均值 - clip_value）
   - 遇到边界拐弯时，优先转向保持沿边界（dir 旋转）
3. 追踪得到的是**连续的单像素宽边界点集**

**当前项目的方法**：
- Otsu 全局阈值二值化 → 形态学 → 逐行从底部向上扫描
- 用 `last_mid` 约束当前行搜索范围
- 问题：Otsu 对光照不均敏感；逐行扫描在急弯中容易跟丢

### 3. 稀疏点集管线 (Sparse Point Set Pipeline)

参考代码将边界表示为 `(x, y)` 点集而非逐行数组，配套一系列处理：

| 操作 | 函数 | 作用 |
|------|------|------|
| 平滑 | `blur_points()` | 加权移动平均（三角核），去锯齿 |
| 重采样 | `resample_points()` | 等距（3px）重采样，消除透视密度不均 |
| 直线延伸 | `addline()` | 两点间线性插值 |
| 贝塞尔延伸 | `add_three_point_bezier()` | 三控制点二次贝塞尔插值（用于圆环弯道） |
| 内缩偏移 | `track_leftline/rightline()` | 沿法线方向偏移 WIDTH/2 生成中线 |

**优势**：
- 重采样使点间距均匀，后续角度/曲率计算更准确
- 贝塞尔插值可平滑连接圆环中的断开边界
- 点集天然适合透视变换

### 4. 角点检测 (Corner Detection)

**`find_corner()` + `seek_corner()`**：
1. 在每条边界的 original_pts 中找 3 个极值点：max X、max Y、max(X×Y)
2. 将极值点映射到 now_pts（鸟瞰图）
3. 在每个候选点附近用 `local_angle_points()` 计算局部角度
4. 取角度变化最大的点作为拐点
5. 用自适应阈值验证该点确实是边界点（非噪声）

**用途**：
- 圆环检测：拐点出现 + 对侧为直线 → 圆环入口
- 十字检测：左右边界拐点距离 ≈ WIDTH → 十字路口
- 十字/圆环导航：在拐点处重新搜索前方边界

### 5. Pure Pursuit 控制律

**当前项目**：固定前视行 `VISION_LOOKAHEAD_Y=85` 取中线偏差 → PD 控制

**参考代码**：
```c
lookahead_dist = clamp(speed * speed_decision, 15, 80);
// 在中线点集上找距离 ≈ lookahead_dist 的目标点
target_idx = argmin(|midline.dist[i] - lookahead_dist|);
// 计算车辆到目标点的方向角作为转向误差
alpha = atan2(target_x - 94, 120 - target_y);  // 度数
```

**优势**：
- 前视距离随速度自适应：高速看远，低速看近
- 方向角天然适合曲率跟踪（弯道内侧的目标点自然产生正确的转向角）
- 不需要区分直道/弯道的不同 PID 参数

### 6. 圆环完整状态机 (9 状态)

| 状态 | 功能 |
|------|------|
| State1 | 检测圆环入口：一侧出现拐点(Lp_state)，对侧为直线(is_straight) |
| State2 | 确认入口：拐点侧边界丢失又出现 |
| State3-4 | 进入圆环：追内圈边界。用贝塞尔曲线补对侧边界 |
| State5 | 出圆环：检测对侧边界的拐点，贝塞尔连接出口 |
| State6-7 | 重回主路：追踪对侧边界直至车体回正 |
| State8-9 | 确认完成：陀螺仪航向角累计 > 阈值，且边界恢复正常宽度 |

**当前项目**：只有 `RING_LEFT` / `RING_RIGHT` 的特征检测，没有导航状态机。

### 7. 速度决策

**`calculate_minihigh()`**：在 `mid_position` 附近 ±6 列用 Canny 向上搜索，找到可见赛道的最远行 → 可见距离

**`calculate_curvature()`**：用 Menger 曲率公式（三点外接圆半径倒数），计算左右边界的平均曲率

**决策**：`curvature * 1000 / 2` + `minihigh` 结合决定速度参数 `decision`，传入 Pure Pursuit 控制 `lookahead_dist`

### 8. 元素序列管理器

- 支持预定义赛道元素序列（如：圆环 → 十字）
- 存储在 Flash 中，断电保持
- LCD 菜单可配置
- 按顺序检测元素，避免误检（例如：只在与序列匹配时才触发 Ring_Process）

## 三、当前项目的不完善之处

### 3.1 视觉管线层面

| 问题 | 现状 | 参考代码的做法 |
|------|------|---------------|
| **无逆透视变换** | 逐行处理，透视畸变导致宽度/曲率失真 | 3×3 透视矩阵，全图鸟瞰变换 |
| **Otsu 全局阈值** | 单阈值对渐变光照（渐晕、阴影）敏感 | 自适应阈值（局部 5×5 均值 - clip） |
| **逐行扫描边缘** | last_mid 连续性约束 + 最宽段优先，急弯中易丢 | 爬墙追踪：沿边界连续跟踪，不依赖行间连续性 |
| **边界表示为逐行数组** | 固定 120 个槽位，缺值为 -1 | 稀疏点集 (x,y)，支持重采样、贝塞尔插值 |
| **角点检测缺失** | 无法检测边界拐点 | 极值点 + 局部角度 + NMS |
| **圆环导航不完整** | 只能检测圆环特征，无导航逻辑 | 9 状态完整状态机 |
| **十字检测仅靠宽度** | `w > base_w + base_w/3` + 碰边界 | 角点距离校验（避免宽直道误检） |

### 3.2 控制层面

| 问题 | 现状 | 参考代码的做法 |
|------|------|---------------|
| **固定前视点** | 第 85 行，与速度无关 | Pure Pursuit：前视距离 = f(speed) |
| **PD 控制中心偏差** | 偏差(px) → 车轮角度 | 车辆到目标点的方向角(°) → 车轮角度 |
| **无曲率速度决策** | FIXED_PWM_DUTY=600 或简单 PID | 曲率 + 可见距离 → 动态速度 |
| **无差速转向** | 仅舵机转向 | 差速 + 舵机（PID_Diff_speed） |

### 3.3 工具链层面

| 问题 | 现状 | 参考代码 |
|------|------|---------|
| **无法离线回放** | 仅 VOFA+ 实时可视化 | NAND Flash 存储压缩图像 + 边界数据 |
| **参数需重新编译** | 修改代码 → 编译 → 下载 | LCD 菜单实时调参 + Flash 保存 |
| **无元素序列** | 全赛道检测所有元素 | 预定义序列，按序触发，减少误检 |

## 四、重点借鉴建议（按优先级排序）

### 优先级 1：Pure Pursuit 控制（可实现性高，效果显著）

**改动范围**：`trail.c` + `control.c`

**方案**：
1. 在 `trail.c` 中生成中线点集（从现有的 `g_track.mid[120]` 逐行数组转换）
2. 计算每个中点到车体 (94, 120) 的距离
3. 前视距离 = `clamp(speed * 0.5, 15, 60)`（参数需调试）
4. 找到距离最接近前视距离的中线点
5. 计算 `atan2(dx, dy)` 转为角度作为转向误差

**预期效果**：弯道跟踪更平滑，不需要为不同弯道类型调整不同的 target 偏移。

### 优先级 2：爬墙式边界追踪替代逐行扫描（可实现性中等）

**改动范围**：`vision_track.c` 的边缘提取部分

**方案**：
1. 保留 Otsu 阈值用于判断像素是否为"赛道"
2. 用自适应阈值（局部 3×3 或 5×5 均值 - clip）替代全局阈值用于边界追踪
3. 实现右手法则沿边界爬墙（参考 `findline_lefthand_adaptive` 的 dir 旋转逻辑）
4. 从底部种子点追踪到顶部
5. 输出从原始点集，再做透视变换（如果性能允许）

**关键代码逻辑**（右手法则爬墙）：
```
方向数组：前(0,-1) 右(1,0) 后(0,1) 左(-1,0)
左前/右前方向根据当前 dir 旋转得到

每步：
  前方像素 < 阈值  → 右转（dir+1），turn++
  左前像素  < 阈值  → 直走
  否则            → 左前走，左转（dir-1）
turn >= 4 → 停止（死路）
```

**难点**：STC32G 性能有限，每像素计算自适应阈值（需要 9~25 次内存读取）可能较慢。可以考虑：
- 只用底部种子点的 Otsu 阈值（不计算局部阈值）
- 或者用 3×3 最小窗口

### 优先级 3：角点检测用于十字/圆环判断（可实现性中高）

**改动范围**：`vision_track.c` + `trail.c`

**方案**：
1. 在边界点集上计算局部角度（`local_angle_points`）
2. 找到角度变化最大的点作为拐点
3. 用拐点信息辅助十字/圆环判断：
   - 左右同时有拐点且距离 ≈ 车道宽度 → 十字
   - 一侧有拐点，对侧为直线 → 圆环入口

### 优先级 4：圆环导航状态机（可实现性中等）

**改动范围**：新建 `ring.c` / 扩展现有 `trail.c`

**方案**（简化版，不需要透视变换）：
1. 检测圆环入口（同优先级 3 角点检测）
2. 丢失一侧边界时，用已知宽度推测对侧
3. 圆环内：追踪内圈，对侧用贝塞尔/直线外推
4. 检测到另一侧角点 → 出圆环
5. 陀螺仪航向角校验完成

### 优先级 5：速度自适应（可实现性高）

**改动范围**：`trail.c` + `control.c`

**方案**：
1. 计算可见赛道距离（向上搜索第一个无边缘的行）
2. 计算中线曲率（三点 Menger 曲率）
3. 直道长视野 + 低曲率 → 高速
4. 弯道短视野 + 高曲率 → 低速

## 五、不建议借鉴的部分

| 技术 | 原因 |
|------|------|
| **逆透视变换 (float 矩阵)** | STC32G 无硬件 FPU，C251 编译器浮点性能有限。188×120 逐像素变换开销太大 |
| **Canny 边缘检测** | 每像素需计算梯度幅值和方向，对 8051 核太重 |
| **NAND Flash 图像存储** | 硬件依赖（需要 W25N04 + SPI 接口） |
| **LCD 参数菜单** | 硬件依赖（需要 IPS200 LCD），当前项目的按键+串口调参够用 |
| **双核架构** | STC32G 是单核，无法分离图像压缩和实时控制 |
| **差速转向** | 当前项目舵机方案已稳定，改机械结构成本高 |

## 六、实施路线图建议

```
第一阶段（1-2天）：
  ├─ Pure Pursuit 控制替代固定前视 PD
  └─ 速度自适应（可见距离 + 曲率）

第二阶段（2-3天）：
  ├─ 爬墙式边界追踪（可选，如果第一阶段弯道仍不稳定）
  └─ 角点检测（用于十字/圆环判断）

第三阶段（3-5天）：
  ├─ 圆环导航状态机
  └─ 元素序列管理（Flash 存储）
```

建议**先做第一阶段**，Pure Pursuit + 速度自适应是两个改动最小、收益最大的改进。如果效果明显提升，再考虑第二阶段更深入的视觉改动。
